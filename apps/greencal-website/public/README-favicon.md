# Favicon assets

`favicon-16x16.png`, `favicon-32x32.png`, `favicon-48x48.png`,
`apple-touch-icon.png` (180x180), `icon-512.png`, and `favicon.ico`
(PNG-format, 32x32 - a fallback for the implicit `/favicon.ico` request
some browsers/crawlers make regardless of `<link rel="icon">` tags) were
generated by resizing the single existing, already-approved logo file
(`assets/greencal/logo/GreenCal Pressure washing logo/greencal-logo.png.png`)
onto a white square canvas at each size - **no new artwork, icon mark, or
design was created.**

## Known limitation

The approved logo is a full wordmark-plus-illustration lockup (dripping
"Green" text, a pressure-washer figure, "GreenCal Pressure Washing"
caption), not a simplified icon mark. At the literal browser-tab size
(16x16-32x32px), the resized result is soft/illegible as fine detail -
this is a resolution limit of the source artwork, not a rendering bug.
It reads correctly at larger sizes (bookmarks, PWA/home-screen icons,
browser new-tab tiles, the 512px asset).

**Recommended future improvement (a real design decision, not performed
here without approval)**: commission or approve a simplified icon-only
mark (e.g., just the sprayer figure or a monogram) sized specifically
for favicon use. This was a known, previously-documented gap (see
`docs/GREENCAL_OWNER_VERIFICATION_REQUIRED.md`) before this fix; this
change resolves the "no favicon at all" defect (previously a 404) with
the best mechanical derivation possible from the current approved asset,
without inventing new branding.
